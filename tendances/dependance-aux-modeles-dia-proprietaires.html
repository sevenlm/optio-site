Dépendance aux modèles d’IA propriétaires

Axe pratiques technologiques · urgence faible

Ce qui se passe

Les organisations construisent prompts, outils et agents autour d’un modèle ou d’une API d’un seul fournisseur. Selon Menlo Ventures, les modèles fermés concentrent 87 % des usages en entreprise, et les fournisseurs retirent régulièrement leurs anciens modèles : OpenAI annonce ces retraits avec six mois de préavis au minimum pour ses modèles généraux.

Le déclencheur

Les organisations industrialisent leurs premiers usages d’IA, souvent autour d’un seul fournisseur de modèles : selon Menlo Ventures, seules 11 % des équipes en ont changé en 2025, alors que les prix et les conditions évoluent très vite.

Le risque pour votre organisation

Changer de modèle peut demander de tout reconstruire, au moment où les prix de l’IA évoluent vite.

Technologies concernées

  • Amazon Bedrock
  • Azure OpenAI (Microsoft Foundry)
  • Claude Code
  • Cursor
  • GitHub Copilot
  • Google Vertex AI (Gemini platform)
  • OpenAI Codex

Comment l’enfermement se met en place

  • Entraînement de l’IA de l’éditeur sur les données clients. Les conditions ou les principes de confidentialité de l’éditeur autorisent l’analyse du contenu client pour entraîner ses modèles, activée par défaut, avec une sortie lourde ou réservée à l’offre la plus haute.

Les leviers pour garder le choix

  • Couches d’abstraction. Prévoyez une couche d’abstraction entre vos applications et les modèles.
  • Modèles d’IA à poids ouverts. Testez régulièrement un modèle alternatif.
  • Passerelle et routage entre modèles d’IA. Rendez le changement de modèle aussi simple qu’un réglage, et prouvez-le par des évaluations.
  • Actifs d’agents de code portables. Gardez instructions et outils des agents de code dans des formats ouverts, indépendants du fournisseur.
