Concentration des régions cloud

Axe pratiques technologiques · urgence moyenne

Ce qui se passe

Le 20 octobre 2025, une panne dans la région US-EAST-1 d’AWS a rendu indisponibles pendant plusieurs heures de nombreux services. Même des applications hébergées ailleurs ont été touchées, car elles dépendaient de cette région.

Le déclencheur

La panne d’AWS du 20 octobre 2025 a rappelé qu’une seule région cloud peut rendre indisponibles de très nombreux services dans le monde.

Le risque pour votre organisation

Être réparti géographiquement ne signifie pas être indépendant : authentification, DNS ou pilotage peuvent créer des dépendances cachées.

Technologies concernées

  • Amazon DynamoDB
  • Amazon S3
  • AWS Outposts
  • Kubernetes managé (EKS, AKS, GKE)
  • Machines virtuelles AWS (EC2)
  • Machines virtuelles Azure

Comment l’enfermement se met en place

  • Concentration sur un prestataire non substituable. Plusieurs services critiques reposent sur le même fournisseur, dont la défaillance touche alors tout le système d’information.

Les leviers pour garder le choix

  • Registre des contrats et des prestataires. Cartographiez les dépendances cachées : identité, DNS, outils de déploiement.
  • Tests de bascule réguliers. Testez une bascule réelle, pas seulement documentée.
